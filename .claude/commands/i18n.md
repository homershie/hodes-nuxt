# 國際化管理 (i18n)

本專案使用 `@nuxtjs/i18n` v10 進行多語言支援。

## 支援的語言

| 語言代碼 | 語言 | 翻譯檔位置 |
|----------|------|-----------|
| zh-TW | 繁體中文（預設） | `i18n/locales/zh-TW.json` |
| en | 英文 | `i18n/locales/en.json` |

**URL 策略：** `prefix`（兩種語系都有前綴）
- 繁中：`/zh-TW/`、`/zh-TW/about`...
- 英文：`/en/`、`/en/about`...
- `GET /` → middleware 自動 302 導向（依瀏覽器語言）

---

## 翻譯鍵命名規範

使用 dot notation，最多 3 層：

```
{namespace}.{section}.{element}
```

**現有命名空間：**
`nav`、`footer`、`home`、`about`、`service`、`contact`、`portfolio`、`blog`、`sidebar`、`pagination`、`breadcrumb`、`related`、`validation`、`structured_data`、`seo`、`404`

---

## 新增翻譯 key

**規則：兩個語系檔案必須同步新增，缺少任何 key 會導致 build 錯誤。**

1. 在 `i18n/locales/zh-TW.json` 新增繁中翻譯
2. 在 `i18n/locales/en.json` 新增英文翻譯
3. 兩個檔案的 key 結構必須完全一致

### 範例

```json
// i18n/locales/zh-TW.json
{
  "blog": {
    "read_more": "閱讀更多",
    "published_at": "發布於 {date}"
  }
}

// i18n/locales/en.json
{
  "blog": {
    "read_more": "Read More",
    "published_at": "Published on {date}"
  }
}
```

## 在組件 / 頁面中使用

### 基本用法

```vue
<script setup>
const { t, locale } = useI18n()
const localePath = useLocalePath()
</script>

<template>
  <!-- 文字翻譯 -->
  <p>{{ t('blog.read_more') }}</p>

  <!-- 帶變數的翻譯 -->
  <p>{{ t('blog.published_at', { date: '2026-01-01' }) }}</p>

  <!-- 所有連結必須包 localePath() -->
  <NuxtLink :to="localePath('/about')">關於我</NuxtLink>
  <NuxtLink :to="localePath({ name: 'blog-page-page', params: { page: 1 } })">部落格</NuxtLink>
</template>
```

### 取得陣列型翻譯（tm）

翻譯檔中的陣列（如旋轉文字、工作經歷）需用 `tm()` 取得，再透過 `useI18nList` 轉換：

```vue
<script setup>
const { tm } = useI18n()
const { toList } = useI18nList()

const headlineWords = computed(() => toList(tm('home.headline_words')))
const experiences = computed(() => toList(tm('about.experiences')))
</script>
```

### SEO Meta（響應式）

```vue
<script setup>
const { t } = useI18n()

useSeoMeta({
  title: computed(() => t('seo.about.title')),
  description: computed(() => t('seo.about.description')),
})
</script>
```

### 表單驗證（computed schema）

`useFormValidation.js` 的 yup schema 已用 `computed()` 包裝，確保語系切換後驗證訊息即時更新。直接呼叫即可：

```js
const { formSchema, ... } = useFormValidation()
```

## 新增頁面時的 i18n 要點

1. 在兩個翻譯檔新增 `seo.{pageName}.title` 和 `seo.{pageName}.description`
2. 所有 `<NuxtLink>` 必須用 `localePath()` 包裝
3. `nuxt.config.ts` 的 `prerenderRoutes` 需同時新增 `/zh-TW/{path}` 和 `/en/{path}`

---

## 部落格文章多語系

文章存放於 `content/{locale}/articles/{slug}.md`：

```
content/
├── zh-TW/articles/my-article.md   # 繁中版
└── en/articles/my-article.md      # 英文版（可相同內容）
```

slug 在兩個語系目錄中相同，路由自動對應 `/{locale}/article/{slug}`。

## 常見問題

1. **翻譯 key 不存在** — 檢查兩個語系檔案是否都有該 key，缺少 key 會在 build 時報錯
2. **連結 404** — 確認 `<NuxtLink :to>` 有用 `localePath()` 包裝
3. **陣列翻譯顯示 `[object Object]`** — 需用 `useI18nList` 的 `toList()` 轉換 `tm()` 回傳值
4. **SEO meta 不隨語系更新** — 確認 `useSeoMeta` 內的值有用 `computed(() => t(...))` 包裝
5. **表單驗證訊息不更新** — `formSchema` 已是 computed，確認 `useForm` 的 `validationSchema` 也是 computed
6. **新頁面找不到** — 確認 `nuxt.config.ts` 的 `prerenderRoutes` 有加入雙語系路由
